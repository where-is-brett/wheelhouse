Update Wheelhouse for the folder this session is in. The host helper makes every change, and only after the director's click; you only talk. Type each command exactly so, one per call, in this folder. (`--no-use-system-ca` keeps Node.js from printing a line for each system certificate. If Node.js answers that it doesn't know that option, run the same command without it.) If the director named a release (`/wheelhouse:update v0.2.8`), put it after `plan`.

1. Say "Looking for the latest Wheelhouse release." Then run `node --no-use-system-ca "${CLAUDE_PLUGIN_ROOT}/scripts/update/cli.js" plan`. If a stop guard answers instead, All stop is on: tell the director to lift All stop first, and stop there.
2. If its answer has no `card`, show its `lines` as they are, and stop. (When nothing is newer, that is one line: the director has the latest.)
3. Ask its `card` with AskUserQuestion exactly as given, with nothing added. Don't mention the hash.
4. If the director chose **Not now**, run `node --no-use-system-ca "${CLAUDE_PLUGIN_ROOT}/scripts/update/cli.js" answer <hash> "Not now"`, with the `hash` from step 1, show its lines as they are, and stop. Their click on the card is what records the decline; this only reports it. Nothing else is done.
5. Only if the director chose **Update**, run `node --no-use-system-ca "${CLAUDE_PLUGIN_ROOT}/scripts/update/cli.js" apply <hash>`, with the `hash` from step 1. It starts the update and answers `started`; the update goes on by itself, and may show the director a password window. Their click on **Update** only starts it: it is never their approval of the change to the project's safety settings, which comes on its own card.
6. Straight after `apply`, run `node --no-use-system-ca "${CLAUDE_PLUGIN_ROOT}/scripts/update/cli.js" wait`, saying nothing before it. It looks at the update every few seconds and answers when the update is `done` or `stopped`, when it has a card for the director, or after a minute and a half. An update that goes straight through is therefore finished in that one call: show its `lines` as they are, and stop. When its answer has `asks`, ask each one's `card` with AskUserQuestion exactly as given, one at a time, and then run `node --no-use-system-ca "${CLAUDE_PLUGIN_ROOT}/scripts/update/cli.js" answer <id> "<label>"` with that ask's `id` and the label the director chose, so the update looks again at once; then run `wait` again. A card is asked once: don't ask it again while a later `wait` or `status` still lists it, unless the director says they didn't answer it.
7. Only when `wait` comes back with `state` still `running` and no `asks`, the update is genuinely waiting for something (work in progress, All stop, a change the host would not merge yet). Show its last line once, then run `node --no-use-system-ca "${CLAUDE_PLUGIN_ROOT}/scripts/update/cli.js" status` about once a minute, saying nothing in between, and answer cards as in step 6, until `state` is `done`, `stopped` or `none`. Then show the `lines` as they are. If `state` stays `unreachable` for several minutes, say what the line says. Don't make up what is happening between checks.
8. If apply says the director has not clicked Update, ask the card again exactly as given and run `apply` only after their click on it. If it says the plan is not the one last shown, start again at step 1. If it says to lift All stop first, tell the director to lift All stop first. If it says a feature session can't run it, say the update is the director's own command, to be typed in their main session.

For how an update stands without starting one, run `node --no-use-system-ca "${CLAUDE_PLUGIN_ROOT}/scripts/update/cli.js" status` and show its lines as they are.
