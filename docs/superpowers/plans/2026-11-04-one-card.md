# One card, one answer: the build plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan part by part. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** While a live pane is beside the First Mate, its cards are answered there and not in the chat. A decided card is never asked again. A stopped chat question loses nothing, and the First Mate's next words state the panel's answer. The pane draws the safekeeping line once.

**Architecture:**
- The bridge marks a live pane per session in `<wheelhouseHome()>/sessions/<id>/`. The question hook (`card-check.js`) reads that mark and denies a card question the pane can answer, or one already decided.
- Each plain card answer records where it was given. One shared module words "approved in the panel at 10:34".
- `board-context.js` hands the First Mate, as context, the answers given since its last turn and the state of any card in a stopped question.

**Tech Stack:** Node.js (ES modules), `node:test`, the mod in TypeScript (`hooks/`). No dependency.

**Spec:** `docs/specs/2026-11-04-one-card-design.md` (the director's rulings are in its section 10).

**How to use this plan.**
- Each part is one fresh session, working from this file, the spec and the repository.
- Each part ends with a pull request and one message to the main session.
- Run the test files a change touches; leave `npm test` to CI.
- Builders ask the main session, never the director.

## Global Constraints

- Every new file starts with its repository-relative path comment.
- British English. Dates as day month year (4 November 2026).
- No model names and no AI attribution in code, comments, commits or pull requests.
- Never name the director's projects or their content: the repository is public. Tests use made-up cards.
- Scripts and hooks are Node.js, so they run on macOS and Windows. Paths come from `node:path`.
- Hooks inform and fail open: a failure in a new check lets the question through (`runAndExit` with `failClosed: false`, as today).
- Context lines never carry a card's id; they name the card by its subject (the composed `parts.what` first line, else the question's first line).
- No release tag.

## Review Focus

1. **A pane the director closed.** The deny must stop within 45 seconds of the last draw, or the chat sends them to a pane they can't see. Tested in Part 3 (stale `pane.json`) and Part 4 (stale means let through).
2. **A non-card question** (a setup step, a plain AskUserQuestion with no set line) in a session with a live pane. It must go through. Tested in Part 4.
3. **Two questions in one call, one decided and one waiting.** The deny names the decided one and tells the First Mate to ask the other through `again`. Tested in Part 4.
4. **A stopped question followed by a panel answer**, the 4 November sequence. The next prompt's context must say "approved in the panel at 10:34", never "no answer". Tested in Part 6 with the 4 November tool result's exact words.
5. **An unreadable or half-written session file** (`pane.json`, `here.json`, `open.json`). It must read as absent, never throw. Tested in Part 3.

### Part 4: The question hook's two denies

**Files:**

- Test: `tests/scripts/hooks/card-check.test.js`

**Interfaces:**

The order inside `decide`: the baseline check (unchanged), then `if (!inProject) return undefined` (unchanged), then the decided-card deny, then the live-pane deny, then the form check (unchanged). When the call goes through, `markOpen(session, ids)` runs for the cards in it.

- **Decided.** A question whose card is no longer waiting because it was decided. The deny reason starts with `DECIDED_LEAD`, "The director has already answered: ". It holds, for each decided card, "<subject>: <answeredWords>". Then: "Ask none of them again, and say so in one plain line. Ask the cards still waiting with `again <n>`." A question matching no card passes.
- **Pane.** Only when the role is `front-desk`, `HOLD_FOR_PANE` is on, `paneLive(session, now)` is true, and `takeHere` doesn't let these ids through. Every question that matches a card the pane gives buttons to (`cardButtons(data).buttons.some((b) => b.does === 'record' || b.does === 'turn')`) is held back. A setup card, a card with no buttons, and a question matching no card pass. The reason starts with `PANE_LEAD`, "These cards are in the panel beside the chat: ", then the count. Then: "Say in one line, before anything else, that <n> card(s) wait in the panel and that you can ask them here instead. Give no card's words, number or id." When other questions were in the same call, it adds: "Ask only the others."
